# Driftward UI and Storybook

Storybook is the catalog for Driftward's shared React components, theme, and
icons. Factory consumes the same `@driftward/ui` workspace that the stories
render. There is no separate demo implementation and no runtime API connection.

## Run the catalog

From the Factory repository, using Node 22.12+ or Node 24:

```bash
npm ci --prefix factory/console
npm run storybook --prefix factory/console
```

Open `http://127.0.0.1:6006`. When running on the VPS, forward that port over SSH
to view it locally. The development server binds to loopback; it is not part of
the production Factory console or its Docker Compose runtime.

The catalog includes seven shared components, their loading/missing/status
examples, live theme swatches, the approved SVG icon set, and agent guidance.
The console's existing appearance is the initial design system. This change
does not adopt Reflect's marketing-site theme.

## Agent access

The running development server exposes a Streamable HTTP MCP endpoint:

```text
http://127.0.0.1:6006/mcp
```

Register it as `driftward-ui` in the agent client's MCP configuration. Clients
must run on this host or use a tunnel: `127.0.0.1` always refers to the client's
machine. The endpoint is local and unauthenticated; keep it on loopback.

1. Discover tools with `tools/list` and call `docs-list` with `withStoryIds: true`.
2. Call `docs-show` for the component's returned ID to read its properties,
   import path, evidence rules, and usage examples.
3. Use `docs-show-story` for additional states and `stories-preview` for previews.
4. Import existing components and icons from `@driftward/ui`; use the shared CSS
   variables. Add a story when adding a component or meaningful state.
5. Run the checks below before handoff.

Storybook 10.6.0 and its MCP addon are pinned. MCP is an upstream preview API.
This setup provides documentation and development tools, not the optional
Vitest `test-run` tool. Our checked-in Playwright checks run through the shell.
Clients without MCP can read `factory/console/ui/index.tsx`, `ui/styles.css`,
`ui/icons.ts`, and `stories/` directly. No global agent settings or Hermes
credentials are changed by installing this workspace. Shared Hermes MCP
registration belongs to the Hermes runtime, never a Factory worker container.

## Source and distribution

| Source | Responsibility |
| --- | --- |
| `factory/console/ui/index.tsx` | Typed, reusable React components |
| `factory/console/ui/styles.css` | Theme tokens, base HTML styles, component styles |
| `factory/console/ui/icons.ts` | Approved, locally bundled Radix icons |
| `factory/console/stories/` | Usage examples, states, and asset catalog |
| `factory/console/src/styles.css` | Factory-specific layout and responsive styles |
| `factory/console/src/model.js` | Factory work stages and evidence semantics |
| `DESIGN.md` | Operator design priorities and validation requirements |

`app.js` and `styles.css` are generated by `npm run build --prefix factory/console`.
The build bundles the shared styles into the existing `/styles.css` endpoint.
`npm run dev --prefix factory/console` watches both JavaScript and CSS.

The package starts at version `0.1.0` and is private. Factory links it using npm
workspaces. To use the same version in another React application:

```bash
npm run pack:ui --prefix factory/console
# In the consuming application:
npm install /tmp/driftward-ui-0.1.0.tgz
```

The package exports TypeScript/JSX source for a React-capable bundler and expects
React 19. Import `@driftward/ui/styles.css` once; it applies global base styles
as well as component classes. Existing applications should inspect those base
styles before adopting them. Icons are included through the pinned MIT-licensed
Radix dependency; stories and Storybook are not runtime dependencies of the
package. Review changes in a PR and bump the package version for releases.
No package has been published to an external registry.

## Validation and sharing

```bash
npm run build --prefix factory/console
npm run check:ui --prefix factory/console
npm run build-storybook --prefix factory/console
# Use the isolated Playwright installation documented in factory/README.md:
NODE_PATH=/path/to/browser-checks/node_modules node tools/test_factory_console_browser.cjs
NODE_PATH=/path/to/browser-checks/node_modules node tools/test_factory_storybook.cjs
```

The Storybook check starts and stops its own loopback server on a temporary
port. It exercises MCP discovery and property documentation, the generated
manifest, every story, keyboard focus, status semantics, and mobile asset
layout. Screenshots contain fictional examples only. Set
`FACTORY_CONSOLE_CHROMIUM` to use a separately installed Chromium executable.

CI builds the catalog, runs these checks, and uploads the static site as the
`driftward-ui-storybook` artifact. The static site in
`factory/console/storybook-static/` can be served by an ordinary static web
server; it includes manifests but **does not run the MCP endpoint**. Persistent
hosting and client registration are separate from this repository setup.

Upstream references: [React/Vite setup](https://storybook.js.org/docs/get-started/frameworks/react-vite),
[MCP](https://storybook.js.org/docs/ai/mcp/overview), and
[component manifests](https://storybook.js.org/docs/ai/manifests).
